# Hubs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three pinnable Hub tiles (Photos, Quick settings, People) that open full-screen Hub pages from Start.

**Architecture:** `HubKind` (key `hub:<name>`) becomes a third `TileContent` variant. `HomeScreen` holds `openHub: HubKind?` and draws a `HubScreen` frame whose body depends on the kind. Android-facing pieces (thumbnail decoding, contacts query, pickers, intents) are injected through a defaulted `HubActions` bundle so every hub is testable with fakes.

**Tech Stack:** Kotlin, Compose, ContactsContract, BitmapFactory, Robolectric 4.13 (SDK 34).

**Spec:** `docs/superpowers/specs/2026-10-16-hubs-design.md`

## Global Constraints

- Package `com.mymetroui.launcher`; minSdk 26; compile/targetSdk 35. No new library dependencies.
- Only one new permission: `READ_CONTACTS`. No `CALL_PHONE`; no phone-number queries.
- No "Windows"/"Phone"/Microsoft names or assets; icons/glyphs are our own text glyphs.
- Unknown `hub:*` keys are skipped, never deleted. Hub tiles are never pruned as "missing apps".
- Photos hub shows at most 60 photos. Contact data stays in memory only.
- Not verified on a device; do not claim otherwise.
- Branch `feat/hubs`. Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- `StartViewModel` prune loop must not delete `hub:*` tiles (they are not apps).
- `READ_CONTACTS` revoked while running (`SecurityException`) → treated as no permission, no crash.
- Photo URI that fails to decode → empty box, others still load.
- Contacts with blank names are skipped; a very long list stays lazy.
- Hub tiles in edit mode: unpin/resize work; tap in edit mode does not open the hub.
- Welcome screen and Back: Back closes an open hub first, before other handlers.
